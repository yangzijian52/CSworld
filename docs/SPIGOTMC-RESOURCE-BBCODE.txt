[CENTER][SIZE=7][B]CSworld Documentation[/B][/SIZE]
[SIZE=4]Installation, Commands, Configuration, Payments and Data[/SIZE][/CENTER]

[COLOR=#ff4d4d][B]Language notice:[/B][/COLOR] The SpigotMC resource page, documentation and support channel are English-only. Chinese-language support is not provided on SpigotMC.
The plugin itself currently displays Chinese messages and ships with Chinese configuration comments.

[SIZE=5][B]Requirements[/B][/SIZE]
[LIST]
[*]Paper 26.2
[*]Java 25 or newer
[*]Vault is required
[*]A Vault-compatible economy plugin is required for paid modes
[*]A configured proxy network that accepts BungeeCord [ICODE]Connect[/ICODE] plugin messages
[*]The proxy destination names must match the keys configured under [ICODE]servers[/ICODE]
[/LIST]

[SIZE=5][B]Installation[/B][/SIZE]
[LIST=1]
[*]Stop the backend Paper server.
[*]Install Vault and, for paid modes, a Vault-compatible economy plugin.
[*]Confirm that the backend server is connected to a proxy that supports the BungeeCord plugin messaging channel.
[*]Place [ICODE]CSworld-1.2.2.jar[/ICODE] in the backend server's [ICODE]plugins[/ICODE] directory.
[*]Start the Paper server once to create [ICODE]plugins/CSworld/config.yml[/ICODE] and [ICODE]plugins/CSworld/data.yml[/ICODE].
[*]Stop the server and configure [ICODE]current-server[/ICODE], destination keys, display names and costs.
[*]Start the server and use [ICODE]/cs[/ICODE] to review the destination list.
[/LIST]

[SIZE=5][B]Player Commands[/B][/SIZE]
[LIST]
[*][ICODE]/cs[/ICODE] - display the configured destinations, payment mode and configured current server
[*][ICODE]/cs <server>[/ICODE] - connect using the proxy server key
[*][ICODE]/cs <display-name>[/ICODE] - connect using the configured display name
[/LIST]

[SIZE=5][B]Admin Commands[/B][/SIZE]
[LIST]
[*][ICODE]/cs reload[/ICODE] - reload [ICODE]config.yml[/ICODE], destination prices, display names and economy mode
[/LIST]

[SIZE=5][B]Aliases[/B][/SIZE]
No command aliases are declared. Use [ICODE]/cs[/ICODE].

[SIZE=5][B]Permissions[/B][/SIZE]
[LIST]
[*][ICODE]csword.reload[/ICODE] - allows [ICODE]/cs reload[/ICODE] - default: OP
[*]Listing destinations and requesting a transfer do not require a plugin permission.
[/LIST]

[SIZE=5][B]Main Transfer Flow[/B][/SIZE]
[LIST=1]
[*]The player selects a configured proxy server key or display name.
[*]CSworld rejects unknown destinations and the destination configured as [ICODE]current-server[/ICODE].
[*]A per-player guard blocks another request during the transfer countdown.
[*]The plugin displays a three-second countdown.
[*]At the end of the countdown, CSworld checks the selected payment mode.
[*]When payment is required, Vault checks the balance and withdraws the configured amount.
[*]In one-time mode, a successful payment stores the player's UUID under the destination in [ICODE]data.yml[/ICODE].
[*]CSworld sends a BungeeCord [ICODE]Connect[/ICODE] message to the proxy.
[/LIST]

[SIZE=5][B]Configuration File[/B][/SIZE]
The main configuration is [ICODE]plugins/CSworld/config.yml[/ICODE]. The following example matches the structure shipped with the plugin:

[CODE]free-mode: false
one-time-payment: true
current-server: "lobby"

servers:
  lobby:
    display-name: "Lobby"
    cost: 0
  skyblock:
    display-name: "Skyblock"
    cost: 1
  survival:
    display-name: "Survival"
    cost: 25[/CODE]

[SIZE=5][B]Common Configuration Options[/B][/SIZE]
[LIST]
[*][ICODE]free-mode: true[/ICODE] - all configured transfers are free; this takes precedence over [ICODE]one-time-payment[/ICODE]
[*][ICODE]free-mode: false[/ICODE] and [ICODE]one-time-payment: true[/ICODE] - pay once for each destination, then keep a permanent unlock
[*][ICODE]free-mode: false[/ICODE] and [ICODE]one-time-payment: false[/ICODE] - pay before every transfer
[*][ICODE]current-server[/ICODE] - the current backend's proxy server key; this is a manual value and must be correct on every backend
[*][ICODE]servers.<key>[/ICODE] - the exact destination name known by the proxy
[*][ICODE]display-name[/ICODE] - the name shown to players and accepted as command input; avoid spaces
[*][ICODE]cost[/ICODE] - a non-negative whole-number amount handled by the active Vault economy provider
[/LIST]

After editing [ICODE]config.yml[/ICODE], run [ICODE]/cs reload[/ICODE] or restart the backend server.

[SIZE=5][B]Data Storage and Backups[/B][/SIZE]
[LIST]
[*]One-time unlocks are stored in [ICODE]plugins/CSworld/data.yml[/ICODE].
[*]Records are grouped by destination and contain player UUID strings.
[*]Per-use payment mode does not add unlock records.
[*]The unlock file is saved immediately after a successful one-time withdrawal.
[*]For a consistent backup, stop the server and copy both [ICODE]plugins/CSworld/config.yml[/ICODE] and [ICODE]plugins/CSworld/data.yml[/ICODE].
[*]Do not remove UUID entries unless you intentionally want players to pay again.
[/LIST]

[SIZE=5][B]Upgrading[/B][/SIZE]
[LIST=1]
[*]Stop the backend server.
[*]Back up the complete [ICODE]plugins/CSworld[/ICODE] directory.
[*]Replace the previous CSworld jar with [ICODE]CSworld-1.2.2.jar[/ICODE].
[*]Keep only one CSworld jar in the [ICODE]plugins[/ICODE] directory.
[*]Start the server and review the startup log.
[*]Run [ICODE]/cs[/ICODE] and confirm the current server, destinations and payment mode.
[/LIST]

CSworld 1.2.2 does not introduce a data migration. Existing [ICODE]config.yml[/ICODE] and [ICODE]data.yml[/ICODE] files remain in the same YAML format. Review new default configuration files separately rather than deleting live data.

[SIZE=5][B]Known Limits[/B][/SIZE]
[LIST]
[*]Only Paper 26.2 is claimed; Spigot server compatibility is not tested.
[*]This release completed a Maven package build, but the project contains no automated test sources and has not been tested on a live Paper 26.2 server.
[*]The plugin does not verify whether a proxy destination exists or is online.
[*]The configured [ICODE]current-server[/ICODE] value is trusted and is not detected automatically.
[*]A successful charge or unlock is not rolled back if the later proxy connection fails.
[*]No automatic refund command or unlock-management command is provided.
[*]Only the first command argument is used as the destination, so display names containing spaces are not supported.
[*]Player-facing messages, administrator feedback, logs and default configuration comments are Chinese.
[/LIST]
